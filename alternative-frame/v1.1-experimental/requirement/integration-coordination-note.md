# 跨板块集成交接说明：软件 Demo 与端边云成员

## 1. 项目分配结论

本轮新增开源项目的直接负责人如下：

| 板块 | 直接接入项目 | 成员需要提供的配合 |
|---|---|---|
| 科研 Demo | `GenExp`、`robin` | 假设、候选、协议、排名和报告接口 |
| 统一评测 | `science-sandbox` | 统一 Oracle、隐藏评测集和跨场景报告 |
| 软件 Demo | 无直接移植项目 | 提供稳定 manifest、测试退出码、重试/恢复运行证据 |
| 端边云 | 无直接移植项目 | 提供节点、路由、回退、暂停/恢复和 runtime view 数据契约 |

## 2. 软件 Demo 成员要求

继续使用已有软件 Demo 分支和冻结接口。不要把 GenExp、robin 或 science-sandbox 的业务代码放入软件 Demo。

需要交付给评测成员：

- 正常、retry-once、local-recovery 三个场景的可复跑入口；
- 每次运行的 `run_id`、`state.json`、`events.jsonl`、manifest 和关键产物；
- 精确测试命令与退出码；
- 失败时的结构化诊断，不以 Agent 文本作为唯一证据。

## 3. 端边云成员要求

继续维护 `feature/edge-cloud-runtime` 既有路由、故障回退、暂停/恢复和节点重新探测能力。不要引入科研领域依赖。

需要交付给评测成员：

- 稳定的 `runtime_view.json` schema；
- 节点状态、路由决策、失败和回退事件；
- 正常、cloud 失败回退 edge、暂停恢复三个样例；
- 明确声明当前是端边云运行时模拟，不能表述为真实多设备部署。

## 4. 集成顺序

```text
科研插件独立验收
-> 评测 Oracle 独立验收
-> 软件/端边云提供稳定数据契约
-> 集成分支逐模块合并
-> 每次合并后跑对应门禁和全量回归
```

任何成员不得直接向正式 `v1.0` 或比赛演示分支推送未经审核的跨模块修改。
