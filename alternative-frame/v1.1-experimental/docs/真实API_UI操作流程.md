# 真实 API 的 UI 操作流程

本流程只针对主界面的“长程任务”模式。API Key 只在窗口内存中使用，不写入本文件、源码或运行证据。

## 打开

双击项目根目录下的 `启动长程任务UI.bat`。如果 Windows 弹出安全提示，确认文件位置是当前项目目录。

## 配置

在左侧模型配置卡片中：

1. “运行模式”选择 **API 模型**。
2. “接口地址”填写你的 API 服务商提供的 OpenAI-compatible Base URL。
3. “API Key”粘贴密钥；不要把密钥写入任务文本或截图。
4. “模型名称”填写服务商真实支持的模型 ID。
5. 保留默认预算：
   - 单次输出上限：`2048` tokens；
   - 本次运行全局额度：`64000` tokens；
   - 模型调用上限：`30` 次；
   - 最长运行时间：`600` 秒。
6. 点击“测试连接”。连接测试只发送一条短消息，不代表长程任务已经完成。

## 执行一个可验收任务

先选择“长程任务”，在目标框输入一个有明确产物和验收条件、又能产生可展示结果的任务，例如：

> 请只在 `runs/outputs/competition_api_demo/` 下创建一个可复现的 CSV 质量分析小项目，不要修改框架源码。分阶段完成：编写简短需求说明；用固定随机种子生成至少 100 条带 `sample_id,score` 列的样例 CSV；实现纯 Python 命令行分析器，检查缺失值、非数值、重复 ID，并输出有效记录数、均值、中位数、最小值、最大值到 JSON 和 Markdown 报告；为正常输入和每类错误各写测试；运行全部测试并实际分析样例 CSV。最终交付源文件、测试结果、样例 CSV、summary.json、report.md，并在报告中列出相对路径和实际测试通过数。

点击“开始任务”。首次运行时检查验收合同预览，确认目标、必需产物和测试要求后再开始。运行过程中观察“任务图”“验收证据”和日志，不要重复点击“开始任务”。

## 查看结果

任务结束后，界面日志会给出状态文件和 API 用量记录路径。运行目录通常位于：

```text
runs/long_horizon/<run_id>/
```

重点查看：

- `state.json`：阶段、完成状态、失败原因和产物引用；
- `events.jsonl`：按时间追加的任务事件；
- `api_usage.json`：本次 UI 运行的额度、可取得的 provider usage，以及缺少 usage 时的本地估算标记。

如果任务暂停，可在“运行历史”中选中该运行并点击恢复。恢复会继续使用原运行的累计额度；不会重置为新的 64,000 tokens。

## 额度含义

`64000` 是一次长程运行的客户端护栏上限，不是服务商承诺一定提供的额度，也不要求模型一定消耗到上限。`2048` 只限制单次请求的输出预算。若服务商忽略 `max_tokens`，客户端会在收到超额 usage 后停止并把该事实写入运行记录。若服务商不返回 usage，`api_usage.json` 会标记为本地估算；它不能替代服务商账单。
