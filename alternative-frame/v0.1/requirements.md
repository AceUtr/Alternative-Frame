# 豆包移动端复刻需求基线

> 任务：`T01_define_requirements_and_doubao_baseline`  
> 状态：需求基线 v1.0  
> 核验日期：**2026-07-28（执行环境本地日期，UTC+8 假定）**  
> 目标平台：**Android 手机**

## 1. 目标与范围

本项目拟实现一个在核心交互与信息架构上对齐豆包官方 APP 的 Android 客户端。客户端通过用户配置的 API 中转站调用模型能力；不复制豆包商标、受版权保护的素材、私有模型、私有协议或服务端实现。

“对齐”指本文件逐项列出的用户可观察流程能够完成并通过验收，不指像素级抄袭，也不保证获得豆包官方账号灰度、付费、地区限定或硬件限定能力。

### 1.1 目标移动平台

| 项目 | 固定要求 |
|---|---|
| 平台 | Android 手机；平板、折叠屏、Android Auto、Wear OS、iOS、HarmonyOS NEXT 不在首版范围 |
| 最低版本 | Android 10（API 29） |
| 目标 SDK | 实施时可用的最新稳定 Android SDK；发布前记录精确 `compileSdk/targetSdk` |
| UI | 原生 Android，支持系统深色模式、动态字体、竖屏；横屏和平板只要求不崩溃 |
| 语言 | 简体中文首发；模型可处理多语言内容，但 UI 国际化不在首版范围 |
| 架构计划 | `app/` 壳与导航；`feature/*` 业务功能；`core/*` 网络、模型、存储、媒体与安全；`benchmark/` 基线证据 |

## 2. 豆包官方 APP 基线

### 2.1 固定方式与当前结论

- **参照产品**：字节跳动官方发布的“豆包”中国大陆移动 APP，不以网页端、桌面端或第三方套壳为基线。
- **参照平台**：Android。iOS 商店元数据仅可作产品能力旁证，不能替代 Android 真机核验。
- **核验日期**：2026-07-28。
- **目标版本**：核验日由豆包官方网站 Android 下载入口实际提供的最新正式版。由于当前研究环境未能从公开页面稳定提取安装包版本元数据，**版本号尚待受控真机核验，不得猜测或以“最新版”永久替代**。
- **版本冻结门禁（P0）**：开始 UI/行为实现前，必须把官方 APK 的 `versionName`、`versionCode`、包名、下载时间、来源 URL、SHA-256、测试设备和账号灰度写入 `benchmark/doubao-android-baseline.md`。无法合法取得 APK 时，改用官方应用商店详情页版本号及页面存档，并记录限制。该门禁未通过前，本文功能清单可用于规划，但不能宣称“完整复刻指定版本”。

### 2.2 证据等级

| 等级 | 定义 | 用途 |
|---|---|---|
| A | 官方网站、官方应用商店元数据或官方帮助/隐私文档 | 确认产品身份、版本、公开能力与政策 |
| B | 指定版本 Android 真机逐屏观察、录屏和无敏感信息截图 | 确认入口、状态、交互、权限和边界 |
| C | 第三方报道或用户描述 | 仅发现线索，不可单独形成验收需求 |

当前功能清单是**公开能力族的完整规划清单**，不是对尚未取得的版本号或账号灰度的虚假确认。P0 门禁后必须对每项标记为“存在 / 不存在 / 灰度不可用 / 条件不可测”，并冻结证据。

### 2.3 核验来源与可复现记录

1. 豆包官方网站：<https://www.doubao.com/>（官方产品身份与下载入口，访问核验日 2026-07-28）。
2. 豆包官方下载页：<https://www.doubao.com/download/desktop>（当前环境成功取得页面响应，但页面未提供可稳定解析的 Android 版本字段，访问核验日 2026-07-28）。
3. Apple 官方 Search/Lookup API：<https://itunes.apple.com/>（当前中国区检索未返回可用于冻结 Android 版本的结果；仅记录失败事实，不据此推断产品下架或版本）。
4. 后续唯一权威的行为证据：第 2.1 节指定 Android 包在受控真机上的录屏、截图、无障碍树和网络边界记录，保存到 `benchmark/`；严禁提交账号令牌、私聊内容或他人个人信息。

## 3. API 中转站边界

### 3.1 中转站必须提供

- 可配置的 HTTPS Base URL、模型 ID 和 API Key；优先兼容 OpenAI 风格的 `/v1/models`、`/v1/chat/completions` 或 `/v1/responses`。
- 文本流式响应（SSE）；明确错误码、超时、限流和用量字段。
- 仅在对应功能启用时提供：视觉输入、图片生成/编辑、语音识别、语音合成、实时语音、文件上传/解析、联网检索和工具调用。
- 能力发现或本地能力配置；客户端不得因为接口“OpenAI-compatible”就假定所有多模态能力存在。

### 3.2 客户端负责

- 密钥加密存储、请求构造、流取消/重试、会话与附件本地状态、能力降级、错误呈现和数据清理。
- 将供应商差异收敛在 `core/model-gateway/` 适配层；业务模块不得直接依赖某一家中转站 JSON。
- 在发送前明确展示将上传的文本、图片、音频或文件；敏感权限按需申请。

### 3.3 明确不由中转站或本项目承诺

- 豆包官方模型的相同权重、系统提示词、搜索索引、推荐排序、声音克隆、数字人、音乐生成、云盘、社区内容及审核策略。
- 豆包官方账号、历史记录、智能体/作品资产迁移，或破解私有 API、签名、风控和付费限制。
- 任何“回答内容完全一致”验收。模型输出只验结构、流程、可用性、安全状态和容错，不验逐字相同。
- 中转站日志、训练使用和跨境传输由运营方承担；客户端必须展示其隐私说明入口，但不能替其作合规保证。

## 4. 外部依赖

| 依赖 | 用途 | 必需性与降级 |
|---|---|---|
| Android SDK、Kotlin、Jetpack Compose、Navigation、Lifecycle/ViewModel | 客户端与 UI | 必需；锁定版本并生成依赖清单 |
| OkHttp/Retrofit、kotlinx.serialization | HTTPS、SSE 与结构化数据 | 必需；证书校验不得关闭 |
| Room、DataStore、Android Keystore | 会话、设置、密钥 | 必需；Key 不得进入日志/备份 |
| Coil | 图片加载与缓存 | 图片功能必需，可清缓存 |
| Media3、CameraX、系统 Photo Picker/文档选择器 | 音视频采集播放与附件 | 按功能启用；拒绝权限时文本聊天仍可用 |
| 中转站及其模型供应商 | 推理与生成 | 必需；能力缺失时隐藏/禁用对应入口并说明原因 |
| 搜索、地图、OCR、文件解析等第三方服务 | 工具增强 | 可选；必须单独配置、披露数据去向 |
| Firebase 等遥测/崩溃服务 | 质量监测 | 默认非必需；启用前需用户同意与脱敏 |

依赖必须使用稳定版本、锁文件/版本目录和许可证清单；禁止把 API Key、签名文件或真实用户数据提交仓库。

## 5. 全局约束与非功能验收

- **隐私**：首次发送任何数据前可查看隐私说明；麦克风、相机、通知按使用时申请；拒绝后有可用降级。设置内可清除单条/全部本地记录和缓存。
- **安全**：仅 HTTPS；生产构建禁用明文流量和敏感日志；密钥使用 Keystore 保护；导出内容默认不含密钥及内部请求头。
- **性能**：基准机（Android 13、8 GB RAM、中端 ARM）冷启动至可操作首页 P95 <= 2.5 秒；长列表滚动无持续明显卡顿；流式首字延迟单独记录网络与服务端耗时，不将供应商延迟伪装为客户端指标。
- **稳定性**：关键 E2E（启动、文本对话、停止生成、重试、历史恢复、断网恢复）连续 30 次成功率 >= 99%；无崩溃、ANR 或会话串线。
- **无障碍**：核心控件有语义标签；TalkBack 可完成文本对话；字体放大 200% 时关键按钮和正文不重叠、不截断。
- **兼容**：至少在 API 29、当前目标 API 各一台设备/模拟器验证；深浅色均通过截图回归。
- **版权与品牌**：使用自有名称、图标、插画和文案；豆包截图只进入访问受控的研究证据，不作为发布资产。
- **测试确定性**：模型内容使用 Mock Gateway 验证协议和 UI；真实中转站只做冒烟测试，密钥由环境变量/本机安全配置注入。

## 7. 逐项验收流程

1. **冻结版本**：完成第 2.1 节 P0 门禁，并为官方 APP 建立首页、会话、输入面板、个人页和全部二级入口的脱敏录屏。
2. **入口穷举**：对可见入口执行广度优先遍历；记录页面、弹窗、长按菜单、系统权限、空/加载/错误/有数据状态。每个入口映射到 F01-F31；未映射数必须为 0。
3. **规格化**：在 `benchmark/feature-matrix.md` 记录官方观察、账号/地区/权限前提、项目预期、差异与证据链接。灰度不可用项不得臆测交互。
4. **自动验收**：单元测试覆盖状态机和适配器；Compose 测试覆盖核心 UI；MockWebServer 覆盖流式与错误；截图测试覆盖关键页面。
5. **真机验收**：至少 API 29 与目标 API 各执行一次核心 E2E。P0 全通过、P1 中被目标发布声明支持的项目全通过，方可发布。
6. **差异验收**：允许品牌、模型输出、供应商能力和合规文案差异；不允许入口无响应、能力误报、数据泄露、会话串线或拒权后崩溃。
