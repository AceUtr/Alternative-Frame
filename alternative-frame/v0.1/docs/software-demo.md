# Software Engineering Demo

This demo proves the shared Alternative Frame Harness can drive a real software
repair workflow with machine-checkable evidence. It uses a small Python fixture
so the flow is deterministic, offline, and fast enough for live presentation.

## Fixture

- Workspace: `examples/software_task`
- Initial defect: `app.py` implements `add(a, b)` with subtraction.
- Regression command: `python -m pytest test_app.py -q -p no:cacheprovider`
- Runtime artifacts: `examples/software_task/artifacts/`
- Long-horizon state: `runs/long_horizon/<run_id>/state.json`
- Event log: `runs/long_horizon/<run_id>/events.jsonl`

`SoftwareDomainAdapter.reset_workspace()` resets the fixture before each run,
removes stale runtime artifacts, and recreates `app.py`, `test_app.py`, and
`requirements.md`.

## Default Demo

```powershell
python run_software_demo.py
```

The default run demonstrates cross-phase recovery:

```text
phase 1:
  inspect_requirements
  inspect_repository
  diagnose_failure
  implement_fix
  run_targeted_tests

global contract:
  missing software_report_exists

phase 2:
  build_change_report
```

Expected high-level output:

```text
Status: completed
Phase count: 2
[phase 1] state=incomplete
Missing criteria: software_report_exists
[phase 2] state=accepted
Missing criteria: none
```

This proves the global evaluator does not accept a successful phase report by
itself. The final goal is accepted only after the missing report evidence is
generated by the recovery phase.

## Local Recovery Scenario

```powershell
python run_software_demo.py --fault-scenario local-recovery
```

This controlled scenario injects one recoverable failure into
`run_targeted_tests`. The local DAG recovery controller freezes the successful
predecessors and reruns only the impacted subgraph.

Expected high-level output:

```text
Status: completed
Phase count: 1
Local recovery cycles: 1
Executed task count: 8
Missing criteria: none
```

The original full DAG has 6 tasks. With local recovery enabled, the system runs
the original DAG plus only the impacted recovery nodes:

```text
frozen:
  inspect_requirements
  inspect_repository
  diagnose_failure
  implement_fix

recovered:
  run_targeted_tests
  build_change_report
```

This proves successful independent nodes are not re-executed when a downstream
task fails.

## Single-Phase Debug Mode

```powershell
python run_software_demo.py --single-phase
```

This mode keeps the original one-phase smoke path for quick debugging and
contribution validation. It is not the main competition presentation path.

## Validation

```powershell
python -m pytest tests/test_software_demo.py -q -p no:cacheprovider
python validate_contribution.py --domain software
```

Current expected result:

```text
tests/test_software_demo.py: 6 passed
validate_contribution.py --domain software: passed
```

The contribution validator checks required files, imports, the
`SoftwareDomainAdapter` interface, preflight readiness, sensitive data, unit
tests, and smoke execution.

## Evidence Artifacts

Each successful run creates:

- `artifacts/requirement_analysis.md`
- `artifacts/architecture_design.md`
- `artifacts/diagnosis.md`
- `artifacts/software_report.md`
- `artifacts/code_diff.patch`
- `artifacts/test_log.txt`

The demo succeeds only when required files and command evidence have current-run
provenance. Stale files and Agent prose are rejected by the acceptance and
global evidence gates.
