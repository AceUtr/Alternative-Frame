# 荣耀 XH-202631 比赛项目计划（截至 2026-09-01）

## 1. 项目定位

暂定项目名：**ResearchSwarm：面向超长程复杂任务的动态异构群体智能引擎**。

以现有 `autoresearch-master` 为起点，但不把作品局限为“自动做科研”。需要把它改造成一个可复用的群体智能底座，并用两个跨领域长程任务证明泛化能力：

1. **科研闭环场景（主场景）**：从研究问题出发，自主完成资料检索、假设生成、实验设计、代码修改、实验执行、结果分析、失败修复与报告生成。
2. **软件工程场景（跨域场景）**：从模糊需求出发，自主完成需求澄清、架构设计、编码、测试、故障注入恢复与交付文档生成。

目标不是宣称真的稳定执行数千次昂贵 LLM 调用，而是提供：可恢复的事件驱动执行引擎、长轨迹回放、自动检查点，以及经实验验证的数百步真实轨迹和千步压力/回放测试。

## 3. 建议技术架构

### 3.1 控制平面

- **Intent Parser**：把高层目标转成约束、验收标准和风险等级。
- **Hierarchical Planner**：生成里程碑 DAG，不一次性展开所有细粒度步骤。
- **Dynamic Router**：根据任务类型、角色能力、负载、成本和数据敏感度，按需创建稀疏通信边。
- **Supervisor/Verifier**：检查产物是否满足验收标准，失败时局部回滚或重规划。
- **Fault Manager**：处理超时、节点失效、工具异常、需求变更和模型降级。

### 3.2 异构执行平面

- 规划、检索、编码、实验、数据分析、评审、安全/隐私等角色采用统一 Agent 接口。
- 每个角色声明 `capabilities / cost / latency / trust / placement / tools`。
- 支持云端强模型、边缘小模型和本地规则/工具执行器；先用模拟 placement 和多模型后端证明调度策略，若有真实端侧设备再补实机实验。

### 3.3 分层记忆

- **Working Memory**：当前子任务的短上下文。
- **Episodic Memory**：事件、决策、结果、错误与恢复记录，采用 append-only event log。
- **Semantic Memory**：压缩后的事实、约束、产物索引和向量检索。
- **Global Blackboard**：只保存全局目标、里程碑状态、关键决策和验收条件。
- 采用重要度、时效性、依赖关系和不确定性联合打分进行压缩/唤醒；每次摘要必须保留来源指针，避免摘要漂移。

### 3.4 低熵通信

所有 Agent 消息使用结构化协议，例如：

```json
{
  "task_id": "...",
  "sender": "experimenter",
  "receiver_capability": "critic",
  "intent": "verify_result",
  "claim": "...",
  "evidence_refs": ["artifact://..."],
  "confidence": 0.78,
  "requested_action": "accept_or_reject",
  "ttl": 2,
  "budget": {"tokens": 800, "seconds": 60}
}
```

路由评分可从可解释的加权模型起步：

`score = capability_match + dependency_gain + uncertainty_reduction - token_cost - latency - privacy_risk`

只把 Top-k 接收者接入本轮子图，并用 TTL、去重、证据引用和预算限制抑制噪声。后期再尝试 bandit/学习型路由，不要在早期押注训练复杂路由模型。

## 4. 里程碑与日程

### 7 月 17-20 日：基线审计与范围冻结

- 将 `autoresearch-master` 放入本工作区，建立可复现环境和一条端到端 baseline。
- 画出现有调用链、状态存储、Agent 角色、工具、模型依赖和失败点。
- 固定两个演示任务及其验收标准；建立评分矩阵。
- 记录 baseline：完成率、总 Token、墙钟时间、LLM 调用数、人工干预次数。
- 输出：架构现状图、差距清单、演示脚本 v0、风险清单。

**退出条件**：新机器按 README 能跑通；主场景至少完成一次短流程；所有指标可采集。

### 7 月 21-27 日：可恢复的长程执行内核（MVP）

- 将任务表示改为持久化 DAG/状态机；每步具备输入、输出、依赖、状态、重试与验收条件。
- 建立 event log、artifact store、checkpoint/resume 和幂等执行。
- 实现 Supervisor + Verifier；任务失败时可重试、换 Agent、局部重规划。
- 接入 OpenTelemetry 或等效 tracing，记录 Agent、边、Token、耗时、错误和产物。

**退出条件**：进程中断后可从检查点继续；工具随机失败 10% 时仍能自动完成短任务。

### 7 月 28 日-8 月 3 日：动态异构拓扑与结构化通信

- 把静态角色链改为 capability registry + 按需组队。
- 实现启发式 Top-k 动态路由、TTL、去重、预算控制和结构化消息协议。
- 前端展示每轮实际通信子图，而不是预设全连接图。
- 建立三组对照：单 Agent、静态多 Agent、动态稀疏多 Agent。

**退出条件**：动态路由能随子任务变化；相对静态全连接通信 Token 至少下降 25%，任务质量不显著下降。

### 8 月 4-10 日：分层记忆与长程稳定性

- 实现 working/episodic/semantic/global 四层记忆与来源指针。
- 实现基于重要度和依赖的压缩、检索与唤醒；加入目标漂移检测。
- 构造 100/300/1000 步回放或混合压力任务，检查约束保留、目标一致性和恢复能力。
- 做消融：无记忆、仅长上下文、摘要记忆、分层记忆。

**退出条件**：300 步真实/混合轨迹中关键约束召回率 >= 95%；1000 步回放无状态损坏；目标漂移能被检测并修复。

### 8 月 11-17 日：端-边-云调度与异常注入

- 为模型/工具增加成本、时延、隐私等级、placement 和健康状态元数据。
- 实现规则型调度：敏感数据优先本地，实时任务优先低延迟节点，复杂推理优先云端。
- 若无端侧设备，以本地小模型/规则执行器、边缘模拟服务、云模型构成可复现实验，并在材料中如实说明。
- 建立故障注入器：节点失效、超时、工具错误、需求中途变更、预算骤减。

**退出条件**：四类故障均能自动恢复；恢复时间、成功率和额外 Token 有量化结果；至少兼容两类模型后端。

### 8 月 18-24 日：两个跨领域 Demo 与界面

- 完成科研任务 Demo：问题 -> 假设 -> 实验 -> 评审 -> 报告。
- 完成软件工程 Demo：需求 -> 设计 -> 实现 -> 测试 -> 故障修复 -> 交付。
- Web UI 展示 DAG、动态拓扑、记忆命中、消息摘要、成本、异常和恢复轨迹。
- 每个 Demo 准备固定种子/缓存回放模式，避免现场网络或模型波动导致失败。

**退出条件**：两个 Demo 各连续成功运行 3 次；全程无人工干预；回放版 10 分钟内可完整展示关键机制。

## 6. 实验矩阵

| 实验 | 对照 | 核心指标 |
|---|---|---|
| 动态拓扑 | 单 Agent / 静态全连接 / 动态 Top-k | 成功率、Token、消息数、耗时 |
| 分层记忆 | 长上下文 / 滚动摘要 / 分层记忆 | 约束召回、目标漂移、完成率 |
